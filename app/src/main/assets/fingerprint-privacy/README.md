# Doulala Fingerprint Privacy

这是供 Chromium MV3 扩展运行时加载的独立指纹隐私模块，不修改 `dola30-original/`。

- 报告只在扩展弹窗本地显示，不上传网络。
- 默认只隐藏 WebGL 调试渲染器信息，其余高影响限制关闭。
- “洁净模式”使用固定的低熵移动 UA、通用设备身份，并通过 MV3 `declarativeNetRequest` 删除高熵 Client Hints；不做随机轮换。
- 用户可选限制 Canvas 读回、离线音频指纹、WebRTC 和媒体设备枚举；这些选项可能影响网页兼容性。
- “严格隐私”会一次开启全部限制，适合不需要绘图、音频或实时通话的页面。
- 只使用固定的隐私化 UA/设备值，不随机轮换，不修改 Cookie、Referer 或认证头，不用于绕过平台风控。

## 当前交付边界

本目录只是 MV3 扩展源码；当前 Android 应用仍使用系统 WebView，没有加载本扩展，Cobalt 尚未接入。不能把源码通过测试当作手机防护已经生效。目标浏览器还必须验证 MAIN world、存储、动态请求头规则及扩展加载支持。

- 洁净模式默认关闭，开启后使用固定的隐私化 UA 和页面可见设备属性；Chrome 140 / Android 13 是固定兼容配置，不代表实际内核版本或硬件。不会修改 Android ID、IMEI 或系统身份。
- 请求头规则影响获准访问的网站；开启和关闭均等待浏览器确认规则更新。失败会显示错误，关闭失败时旧规则可能仍在，需重试或禁用扩展。规则不触碰 Cookie、Referer、Authorization。
- 已有页面的 JS 属性必须刷新后才应用或恢复。初次注入依赖异步读取设置，不能保证网站首个脚本读取前完成。
- 页面层限制仅作用于顶层页面，不覆盖 iframe、Worker、原型直接调用等路径；MAIN world 脚本、设置桥与本地报告均可能受页面脚本干扰，不是对抗恶意页面的隔离边界，也不是内核级反指纹。
- IP、账号、Cookie、屏幕、时区等仍可能关联用户；固定属性组合也可能增加可识别性。不能保证阻止定向广告或实现匿名，严格模式可能破坏正常网页功能。

## 验证与回退

在支持本清单 API 的 Chromium 扩展运行时中手动加载本目录进行测试。使用自有回显页面核对实际网络 UA / Client Hints，与页面 navigator 值对照；开关各切换两次并刷新页面，确认关闭后恢复原始值。测试 iframe、Worker 应明确记录为未覆盖，而不是通过。

Node VM 行为测试覆盖属性恢复、请求头规则构造、并发顺序、失败提示与恢复；它不验证真实浏览器是否接受规则，也不证明所有请求都会被处理。最终必须做 Android 真机和网络回显验证。

新增 `tests/fingerprint-browser.cjs` 真实 MV3 测试：本地 Chromium 153 已验证两次开关、请求头与页面 UA 一致、关闭恢复、Cookie/认证头保留、严格模式 Canvas 阻断；仅访问本机测试服务。该结果不代表 Cobalt 140 或 Android 已通过。GitHub 工作流会重复运行并生成独立扩展 ZIP。
