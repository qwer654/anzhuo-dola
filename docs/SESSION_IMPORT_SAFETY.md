# CK 导入与空间稳定性（0.3.4）

## 报告与本次修复的边界

用户提供的桌面 Cici 测试报告记录了导入会话发送后出现 `710022002`、随后登出及会话过期的链条。报告没有提供 Android WebView 的同条件对照，也没有证明持久目录可以阻止服务端拒绝；新旧账号、IP、设备语境等因果判断不能仅凭该样本完全排除。

本迭代不承诺修复服务端风控或恢复已过期 CK，不执行发消息测试、不补造设备 cookie / localStorage、不修改 completion 请求、不拦截网站真实 logout，也不尝试隐藏邮箱登录 API。

## 已有持久隔离

`space0` 到 `space63` 的进程、WebView 数据目录和缓存目录是固定的。普通退出、进程回收后重开、归档/恢复不会换目录，不清 Cookie 和网页 localStorage。明确执行“清除”或“删除”才重置该空间。64 个档案不等于 64 个同时常驻进程，也不等于不同 Android UID。

## 新增本地导入尝试档案

- Dola CK 文件及 Dola 站点的普通 Cookie 快照都在最终确认后、任何 Cookie 写入前检查。
- 对验证后的完整 Cookie 名值集合排序，以应用安装级随机 32 字节密钥计算 HMAC-SHA256；仅保存摘要和空间号，不保存明文 CK、UID、邮箱、设备 ID 或网页内容。
- 文件位于应用私有 `noBackupFilesDir/ck-import-bindings`，不参与系统备份；跨进程锁及原子替换避免同时导入同一 CK 到两个空间。
- 完全相同 CK 已在其他空间有导入尝试时拒绝写入，并提示回原空间。不能从摘要认定真实账号；CK 内容变化或会话轮换后可能无法查重。
- 同一空间允许重试相同 CK，也允许用户明确确认的不同快照（避免要求刷新 CK 必须清目录）。保留最多 16 份尝试摘要，不自动淘汰旧摘要；达到上限则拒绝新导入，可继续官网登录。
- 预留记录先落盘，因此崩溃、取消导航、零项成功、部分失败都可能留下保守的尝试档案。它不是“导入成功”或“已登录”标记，不会自动回滚、重试、发送或换号。
- 导入确认提示 CK 不含完整网页设备语境及原 Cookie 属性，优先原空间官网登录。清除/删除成功时仅释放该空间摘要，归档/恢复保留；释放失败维持 reset pending，重试完成前不开放档案。
- 摘要保护仅覆盖同一 APK 安装实例，不检测另一个包、外部浏览器或其他设备，不覆盖升级前未记录的历史导入和手动官网登录。

## 验证范围

新增测试仅用合成 Cookie：顺序无关、同空间重开、跨空间拒绝、同空间刷新、私密性、随机密钥、多线程竞态、损坏记录拒绝、容量上限、清除/删除只释放本空间和 UI 警示取消。不读取真实 CK，也不发送真实账号消息。

设备测试使用一次性 CI 模拟器验证包。不要在含真实空间的手机上运行会清理 fixture 的 instrumentation 测试。

此前 GitHub 临时 debug 签名与手机已安装包不匹配。生成新 APK 不意味着可无损覆盖旧安装；未配置持久签名时，不以卸载旧包规避签名检查。用户提供的私有根因报告及账号材料不上传仓库。
